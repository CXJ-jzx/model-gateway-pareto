# 轻量繁忙判断：第一阶段

本阶段只实现容量压力判断。它为后续“繁忙时速度优先、短窗口攒批和请求重排”提供信号，不实现队列、自动切换评分、请求长度影响预测或容量预留。

## 1. 判断依据

只读取 `(model_id, endpoint_id)` 的容量和当前用量，不使用 Endpoint 聚合 RPM/TPM/并发，不扫描历史日志和性能窗口。

```text
RPM 利用率 = current_rpm / capacity_rpm
TPM 利用率 = current_tpm / capacity_tpm
并发利用率 = current_concurrency / capacity_concurrency
pressure = 三项已知利用率的最大值
```

默认进入阈值为 `0.8`，退出阈值为 `0.6`，由 `BusyThresholds(enter, exit)` 配置。这是未经过负载实验标定的起始参数，不是供应商限额，也不是 SLO。

- 未繁忙：`pressure >= enter` 时进入繁忙。
- 已繁忙：`pressure > exit` 时维持繁忙；三项容量已知且 `pressure <= exit` 时恢复。
- 当前用量达到上限：在 `saturated_dimensions` 中记录；压力繁忙不要求已经满载。
- 比率超过 1 不截断，方便发现计数或超发异常。
- 容量未知：不能证明低压力；但某一已知维度达到阈值，足以证明繁忙。
- 上限为 0、禁用、健康异常或仍在 Cooldown：标记 `unavailable`，不混成容量繁忙。健康 `unknown` 沿用当前路由的处理规则，不在此模块额外拒绝。

采用进入/退出不同的阈值，避免临界点频繁切换。只缓存每个组合的繁忙记忆位，不复制用量计数。部分容量未知时，低压力不能证明恢复，记忆位可保留，但本次结果可能是 `unknown`。

## 2. 模型层面的结果

| status | is_busy | 含义 |
| --- | --- | --- |
| `idle` | `False` | 判断范围内存在一个三项容量已知且不繁忙的 Endpoint |
| `busy` | `True` | 判断范围内所有未排除 Endpoint 都繁忙 |
| `unknown` | `None` | 没有已知低压力替代，但部分 Endpoint 的证据不足 |
| `unavailable` | `None` | 没有 Endpoint，或判断范围内全部被排除 |

每个 Endpoint 的局部状态仍单独返回。一个 Endpoint 热、另一个低压力时，模型整体为 `idle`，不会因满载比例高就自动让整个模型等待。`busy_fraction` 只作监控，是确定繁忙数量除以未排除数量，未知 Endpoint 也在分母中；无未排除 Endpoint 时为 `None`。

**这是容量压力，不是请求可行性。** `idle` 不代表当前请求的长度一定放得下，也不保证价格和 SLO 合适。模块不检查价格、SLO、性能证据或请求长度；调用方可以传入已筛选的 `endpoint_ids` 子集，避免把不满足当前请求要求的 Endpoint 当作替代资源。报告中的 `scope` 标明判断的是整个模型还是子集。

`is_busy` 是三值信号，不能简单用 `if not result.is_busy` 将 `unknown/unavailable` 当作空闲。未来调度器应明确处理四种 `status`。

## 3. 代码入口与数据流程

```text
调用方更新组合用量
  → ModelEndpointRegistry.update_model_endpoint_load()
调用繁忙判断
  → InMemoryRoutingState.assess_busy()
  → BusyDetector.assess()
  → ModelEndpointRegistry.capacity_snapshot()
  → BusyDetector._assess_endpoint()
  → BusyAssessment
```

- `memory_state.py::capacity_snapshot()`：在一把锁内读取当前模型的组合状态和整体健康，包含已满 Endpoint，返回版本号；只遍历当前模型索引。
- `busy.py::BusyThresholds`：校验 `0 <= exit < enter <= 1`。
- `busy.py::BusyDetector`：逐组合判断并维护阈值记忆；只支持按时间正序评估，同一时刻重复调用允许。新一轮回放使用新状态。
- `BusyAssessment.to_dict()`：输出阈值、比率、原因、分类集合、版本和时间，便于核验。
- `state.remove_endpoint()`：清理相应繁忙记忆。直接通过 catalog 删除时，下次评估会清理不再注册的组合。

调用示例，假设 `state` 已初始化并注册 Endpoint：

```python
from endpoint_routing_strategy import BusyThresholds, InMemoryRoutingState

state = InMemoryRoutingState(busy_thresholds=BusyThresholds(enter=0.8, exit=0.6))
# 注册配置后，由网关或实验驱动维护当前用量：
# state.catalog.update_model_endpoint_load("模型A", "端点1", current_concurrency=8)

result = state.assess_busy("模型A")
print(result.status)
print(result.to_dict())

# 针对请求，未来调用方可传入已经检查 SLO 等条件的候选集合：
# result = state.assess_busy(request.model_id, at_time=now, endpoint_ids=eligible_ids)
```

计算和额外状态均为当前模型 Endpoint 数量的线性规模；不定时轮询、不调用远端、不计算 P95/Pareto。原有 `RoutingEngine.route_request()` 保持不变，尚未自动调用这个信号。

当前用量依赖调用方正确更新；本阶段没有增加 RPM/TPM 自动滑动计数器。`at_time` 用于评估时间及 Cooldown 比较，不会自动还原该时间的历史负载，也不证明缓存新鲜。

## 4. 执行与验证

在项目根目录执行：

```powershell
python -B -m endpoint_routing_strategy.experiments.busy_check

# 自定义阈值
python -B -m endpoint_routing_strategy.experiments.busy_check --enter-threshold 0.9 --exit-threshold 0.7

# 专项测试
python -B -m unittest endpoint_routing_strategy.tests.test_busy -v

# 全部回归
python -B -m unittest discover -s .\endpoint_routing_strategy\tests -v
```

实验使用明确标记的合成用量快照，验证空闲、局部热、全部热、阈值记忆、恢复、满载、模型隔离、禁用和容量未知。输出自动放在 `experiments/output/busy_check_时间戳/report.json`，包含输入快照、判断结果、检查是否通过、单次计算时间和源代码哈希。结果目录不覆盖已有目录。

单次计时只作诊断，不代表稳定性能基准；这些场景证明规则实现，不证明阈值最优，也不证明平均时延已经改善。后续再接速度优先与有界队列，并验证其效果。
